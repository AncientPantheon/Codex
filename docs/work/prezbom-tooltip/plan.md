Calls `tryGetEntrypoint(entrypointKey)`; returns `null` if not found (unknown key). Else calls `getPreview(ep.preview)` (returns `null`/throws-safe via optional chaining if `ep.preview` is falsy — treat a missing preview the same as `null`, rendering the exec-signature-only view with no live-cost section). For each preview param `p`: value = `callerValues?.[p.name] ?? ep.ghost.args[p.name] ?? placeholderForType(p.type)`; track whether it came from caller/ghost (`isPlaceholder = false`) or the fallback (`isPlaceholder = true`) or is `undefined` (unresolved — no safe placeholder for this param's type). Returns `unresolved: true` if ANY param has no value at all; returns `allPlaceholder: true` if EVERY param's value came from the fallback (none from caller or ghost).
    - `function useTooltipEntrypointWarning(entrypointKey: string, found: boolean)` (or inline in the card) — module-scope `const warnedKeys = new Set<string>()`; on an unresolved key, `console.warn` exactly once per distinct key (deduped via the module-scope `Set`), never per render/hover.
    - `PreZbomTooltipCard({ entrypoint, values }: { entrypoint: string; values?: Record<string, unknown> })` — declared at MODULE SCOPE. Resolves `ep = tryGetEntrypoint(entrypoint)`. If `!ep`: fires the deduped warning once, renders a minimal "not on chain — this button names a function the registry does not define" card (mirrors `ExecutionTooltipCard`'s existing not-found copy) and returns early — no live read attempted. Otherwise renders: (1) the EXEC line — `entrypoint` plus `ep.params.map(p => p.name)` as a reference signature (labelled, e.g. "executes:"); (2) the PREVIEW line — `ep.preview` plus the merged values from `buildMergedPreviewValues`, each preview param shown as `name = value` (never positioned against `ep.params` — this is the brief's "arguments belong to the PREVIEW" trap); (3) the live cost section, rendered via `usePreZbomPreview` below, UNLESS `buildMergedPreviewValues(...).unresolved` is true (render "no cost preview — a required argument has no renderable type" instead) or `.allPlaceholder` is true (render "no cost preview — no live example on chain" instead, matching the design's ghost-count-gate).
    - `function usePreZbomPreview(entrypoint: string, mergedValues: Record<string, unknown> | null): Preview` — the live-read hook. Computes `const callString = mergedValues ? (() => { try { return buildPreviewCall(getEntrypoint(entrypoint).preview!, mergedValues); } catch (e) { return null; } })() : null` in the render body (NOT inside the effect), and passes `callString` itself as the `useEffect` dependency (the brief's 3rd trap: never key on a `values`-shaped object literal, which is a new identity every render — key on the RENDERED STRING, which is referentially stable across renders when the underlying values haven't changed). Debounced 250ms via `setTimeout`, cached in a module-scope `Map<string, Preview>` keyed on `callString`, using this package's own `pactRead` from `@stoachain/stoa-core/reads` — mirrors `ExecutionTooltip.tsx`'s `useExecutionPreview` almost verbatim (same `Preview` state union, same debounce/cache shape), the difference being the call string comes from `buildPreviewCall` instead of a hand-built template literal.
    - `PreZbomHint({ entrypoint, values, children }: { entrypoint: string; values?: Record<string, unknown>; children: React.ReactNode })` — the exported default, declared at MODULE SCOPE (never inline inside `OuronetAccountsTab`/`SingleApiPanel`/`DualApiPanel`'s render bodies — the brief's 4th trap: a component declared inside another component's render function gets a new identity every parent re-render, which React treats as a new element TYPE, unmounting and remounting the whole subtree — exactly OuronetUI's flicker bug). Reads `const { enabled } = usePreZbomTooltipSetting()` and `const isMobile = useIsMobile()` (from `@ancientpantheon/codex-ui/ui`). If `!enabled || isMobile`, returns `<>{children}</>` with NO `PreZbomTooltipCard` mounted at all (so `usePreZbomPreview`'s effect never fires — "off means off: no read fires," satisfied structurally, not by a runtime early-return inside the effect). Otherwise wraps `children` in `<ActionTooltip content={<PreZbomTooltipCard entrypoint={entrypoint} values={values} />} side="bottom">` (reusing the existing Radix-based `ActionTooltip` from `../ui/ActionTooltip.js` — already lazy-mounting and already using Radix's pointer-event-driven `Tooltip.Trigger`/`Tooltip.Content`, so the brief's "use pointer events, not mouseleave" trap is satisfied by construction, not reimplemented).
